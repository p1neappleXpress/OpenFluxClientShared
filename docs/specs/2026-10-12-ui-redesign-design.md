# Переработка интерфейса OpenFlux Android / Desktop: дизайн

Дата: 2026-10-12. Статус: на утверждении владельцем.
Касается: общий модуль `OpenFluxClientShared` (сабмодуль `shared/` в `OpenFluxAndroid` и `OpenFluxDesktop`), ветка `nav3`.

## 1. Цель

1. Перевести навигацию с Voyager и ручного `AppNav` на Compose Navigation 3 (JetBrains `navigation3-ui`), с predictive back на Android и восстановлением стеков.
2. Перестроить интерфейс по образцу AmneziaVPN: лаконично, одна главная функция на экране, все функции на месте.
3. Полностью переделать работу со своим сервером: мастер ноды и редактор ноды с применением изменений.

Ориентир — AmneziaVPN по устройству и лаконичности. Редактор ноды образца у Amnezia не имеет и проектируется здесь; он — самое функциональное место приложения.

## 1a. Подход: интерфейс пишется заново

Старые экраны не переносятся и не правятся: каждый экран, диалог, модель экрана и компонент пишется заново по этому документу, зная заранее весь перечень функций (раздел 11).

| Слой | Решение |
|---|---|
| `ui/**` — экраны, диалоги, оболочка, навигация, модели экранов (`*ScreenModel`, `NodeWizardModel`, `PhpWizardModel`) | **пишется заново** в новом пакете `io.openflux.app`; старое удаляется |
| `ui/theme`, `ui/components` | **пишется заново** (раздел 3a) |
| `model/`, `service/` (`AppContainer`, интерфейсы платформы, SSH, подписка, аккаунты, обновления), `data/`, `androidMain` / `jvmMain` / `jvmSharedMain` | **остаётся**; меняется только там, где новому интерфейсу не хватает API, отдельными коммитами с тестами |

**Замена — параллельно.** Новый интерфейс растёт в пакете `io.openflux.app` в ветке `nav3`, рядом со старым `io.openflux.desktop.ui`, который не меняется и продолжает работать. Точка входа нового — `OpenFluxApp2(container, …)` с той же сигнатурой, что `OpenFluxApp`; приложения переключаются на него одной строкой (в отладочной сборке — флагом, чтобы сравнивать). Когда новый интерфейс покрывает раздел 11, старый `ui/**` и Voyager удаляются одним коммитом, `OpenFluxApp2` переименовывается в `OpenFluxApp`, и только тогда ветка вливается в `main`. До этого `main` и выпуски 2.14.x не затрагиваются.

Незакоммиченная правка старого интерфейса в ветке `nav3` (перевод старых `ScreenModel` на `ViewModel`, удаление `*Tab`) с этим подходом не совместима: она сохраняется коммитом в ветку `wip/nav3-old-ui-migration` для справки, а `nav3` возвращается к `main` + этот документ. Из неё в новый пакет переходят `ListDetailSceneStrategy`, `destEntry` и `PlaceSceneTest`, зависимости `navigation3-ui` / `lifecycle-*` в каталоге версий.

## 3a. Дизайн-система

Своя, в духе AmneziaVPN, с нуля; на Material 3 как основе (поля, меню, шторки, системное поведение), но со своими токенами и компонентами.

- **Тема:** тёмная по умолчанию, светлая и «как в системе» — по настройке. Почти чёрный фон, поверхности на ступень светлее, один акцентный цвет (тёплый оранжевый, как у Amnezia), отдельные цвета состояний (подключено, ошибка, предупреждение). Токены: цвета, типографика (заголовок экрана, строка, подпись, моноширинный для адресов и ключей), отступы, радиусы.
- **Компоненты:**
  - `ConnectButton` — крупная круглая кнопка с состояниями и временем;
  - `RowItem` — строка списка: значок, заголовок, вторая строка, значение/переключатель/шеврон/⋮; основа почти всех экранов;
  - `Section` — группа строк с заголовком; `Collapsible` — «Дополнительно»;
  - `ScreenScaffold` — заголовок со стрелкой «назад» и действиями, прокрутка, место под нижнюю панель;
  - `PrimaryButton` / `SecondaryButton` / `TextButton` / `DangerButton`;
  - `Banner` — одна строка, тон, действие;
  - `ProgressLine` — строка хода операции с полосой и «Подробнее»;
  - `ChangesBar` — панель «Изменено: N · Отменить · Применить» с ходом и ошибкой;
  - `Field`, `SecretField`, `Segmented`, `Switch`, `Chip`;
  - `Sheet` — шторка (телефон) / панель или диалог (десктоп); `ConfirmDialog`; `Toast`;
  - `QrView`; `StatusDot`; `TransportIcons`.
- Каталог компонентов — тест, рисующий их в PNG в обеих темах и на узком экране, для ревью глазами (как каталог в `product-app`).

## 2. Ограничения

- `node-install.sh` **не меняется.** Редактор ноды пользуется только операциями, которые скрипт умеет сейчас: `probe`, `plan`, `apply`, `list`, `show`, `set-transports` (транспорты и режим L3/L4, с откатом на сервере), `set-cookies`, `remove`, `upgrade`, `autoupdate`, `uninstall`. Смена порта, ключа, запуск/остановка, журнал ноды на сервере, трафик — вне этой работы.
- Функции приложения не теряются. Всё, что есть сейчас (перечень — раздел 11), остаётся доступным; меняется место и способ.
- Ядро OpenFlux не меняется.
- Это экспертные приложения (production.md, A5 «Отдельно»), не продукт `product-app`.

## 3. Правила интерфейса

1. **Без информационных карточек.** Факты — строками «название · значение»; пояснения — одной строкой там, где без них ошибутся, иначе не пишутся. Нет заголовков-подписей вида «Главная / Состояние подключения и трафик».
2. **Один баннер на экран**, по приоритету; баннер всегда с действием.
3. **Ход операции — одной строкой** и полосой прогресса; подробности (журнал) — по ссылке «Подробнее».
4. **Ошибка — одна причина и действия** ([Повторить], [Журнал], отмена/удаление по смыслу).
5. **Редкое — под «Дополнительно»** (свёрнуто), а не на виду.
6. **Сочетания клавиш** — во всплывающих подсказках кнопок, не в подзаголовках.

## 4. Разделы и навигация

### 4.1 Разделы

Телефон (ширина < 600 dp) — нижняя панель; шире — боковая колонка (свёрнутая до значков < 1000 dp, как сейчас).

**Главная · Серверы · ＋ · Поделиться · Настройки**

| Раздел | Содержит |
|---|---|
| Главная | кнопка подключения, шторка выбора подключения, экран профиля, редактор профиля |
| Серверы | свои серверы (SSH), ноды на хостинге, «Это устройство» (режим выходной ноды), мастера, редактор ноды |
| ＋ | не раздел: меню добавления (раздел 7.1) |
| Поделиться | выбор, чем делиться, и экран отдачи |
| Настройки | категории, аккаунт и подписка, сервисы, журнал, транспорты на JS, о программе |

Раздела «Подключения» больше нет: список подключений — шторка на Главной.

Сочетания клавиш: Ctrl+1…4 — Главная, Серверы, Поделиться, Настройки; Ctrl+Enter — подключить/отключить; Ctrl+N — новый профиль; Ctrl+I — «Ключ, ссылка или файл»; Ctrl+S / Esc в редакторах.

### 4.2 Хозяин экрана и «назад»

1. **У каждого экрана один раздел-хозяин** (таблица 4.1; вход в аккаунт и подписка — Настройки; экран отдачи — Поделиться; ключ/ссылка/файл — Главная). Переход из другого раздела переключает на хозяина и кладёт экран в его стек.
2. **«Назад»** снимает экран со стека раздела; с первого экрана раздела — на Главную; на Главной — выход из приложения (Android) / ничего (десктоп).
3. Нажатие на вкладку текущего раздела — к его первому экрану; на другую — туда, где человек её оставил.
4. Удалённый профиль или нода убирает из всех стеков экраны, которые их показывают.

### 4.3 Устройство на Navigation 3

- **Ключи:** `Dest` — `@Serializable sealed interface Dest : NavKey`; параметры экранов — только идентификаторы (строки), не объекты.
- **Стеки:** по `rememberNavBackStack` на раздел; выбранный раздел — `rememberSaveable`. На Android стеки переживают смерть процесса. На десктопе стеки и раздел сохраняются в настройки при закрытии окна и восстанавливаются при запуске; экраны, чьих профилей или серверов уже нет, отбрасываются.
- **`AppNavigator`** (замена `AppNav`): держит стеки и раздел, реализует правила 4.2 (`open(dest)`, `back()`, `select(section)`, `forget(id)`); чистый класс над `SnapshotStateList`, покрыт тестами без UI.
- **Показ:** `NavDisplay` текущего раздела; `entryProvider` — единственное место соответствия `Dest` → экран (замена `DestContent`); predictive back на Android через `NavDisplay`.
- **Сцены:**
  - `ListDetailSceneStrategy` (начата в ветке `nav3`): в окне ≥ 900 dp раздел Серверы — список слева, сервер/нода справа; Настройки — категории слева, страница справа.
  - Шторка выбора подключения — `OverlayScene` (bottom sheet), «назад» её закрывает. В окне ≥ 900 dp шторки нет: список — постоянная панель справа от кнопки.
- **Модели:** `ViewModel` (`lifecycle-viewmodel-navigation3`) на запись стека: мастер и редактор ноды живут, пока их экран в стеке, и освобождают SSH-сессию в `onCleared` (замена ручного `release()` / `onRemoved`). Общие модели (профили, подписка, настройки) — в объекте приложения со своим `ViewModelStore`, живут, пока живёт `OpenFluxApp2`.
- **Уходит** (вместе со старым интерфейсом, раздел 1a): Voyager (все четыре артефакта), `AppNav`, `PlaceHost`, `TabNavigator`, объекты `*Tab`.

## 5. Свой сервер

### 5.1 Мастер «＋ → Свой сервер»

1. **Сервер.** Адрес (`host` или `host:port`), Логин (по умолчанию `root`), переключатель «Пароль / Ключ» (ключ: текст или [Файл…], парольная фраза). Над формой — чипы недавних серверов. Под «Дополнительно» — пароль sudo, источник ядра. Кнопка [Подключиться]. Отпечаток ключа сервера — диалог (новый: [Доверять]; изменился: [Сервер переустановлен], опасное действие).
2. **Как ставить.**
   - **Быстро:** нода только с `direct`, режим L3, если сервер его поддерживает (`probe`), иначе L4; автообновление включено. Одно нажатие — установка.
   - **Настроить:** редактор ноды (5.3) в режиме создания; вместо «Применить» — «Установить».
3. **Установка.** Одна строка этапа и полоса прогресса; «Подробнее» — журнал мастера. Ошибки `plan` показываются у кнопки «Установить» до запуска. Проверка подключения после `apply` — часть установки; ожидание капчи Яндекса — строкой с [Хватит ждать]. Ошибка: причина, [Повторить], [Журнал], [Удалить с сервера], [Сохранить профиль всё равно].
4. **Готово:** открывается экран ноды (5.3) вместо мастера; профиль на этом устройстве добавлен; короткое уведомление «Нода установлена». Отдельного экрана «Готово», шага «План» и «Шаг X из 4» нет.

Уход из мастера с введёнными данными — вопрос «Выйти без сохранения?».

### 5.2 Экран сервера

Заголовок `user@host`, точка состояния SSH. Сохранённый доступ — подключается сам при открытии; иначе форма входа (5.1, шаг 1) на месте содержимого.

- **Вкладка «Ноды»:** строка на ноду — имя, порт, значки транспортов, точка состояния (по `list`); нажатие — редактор ноды. [＋ Нода] — 5.1 с шага 2. Пустой сервер — одна строка и [＋ Нода].
- **Вкладка «Сервер»:** строка «система · версия ядра»; переключатель «Автообновление ядра» (`autoupdate`); [Обновить ядро на всех нодах] (`upgrade`); «Изменить доступ» (SSH); «Забыть сервер»; «Удалить OpenFlux с сервера» (`uninstall`, подтверждение с перечнем нод).

### 5.3 Редактор ноды

Один компонент для создания и изменения.

**Шапка:** имя, точка состояния, `адрес:порт` (только чтение); [Подключить себе] [Поделиться]; ⋮ — Обновить состояние (`list`/`show`), Удалить с сервера (`remove`, подтверждение).

**Настройки:**
- **Транспорты** — строка на транспорт: переключатель и поле в строке. Яндекс Документ, Yandex Docs, Mail.ru Документы, Яндекс Доска — ссылка или [Войти и создать] в той же строке; Cups.online — комнаты генерируются сами; `direct` — всегда включён, показывает адрес. У транспортов Яндекса — строка «Передать вход на сервер» (`set-cookies`) с подтверждением.
- **Режим** — L4 / L3, одна строка о разнице; L3 недоступен, если сервер его не поддерживает.
- **Дополнительно** (свёрнуто): имя (хранится на устройстве), автообновление ядра.

**Применение:**
- Правки копятся в черновике. Внизу панель «Изменено: N · [Отменить] [Применить]».
- [Применить] → `set-transports`; ход — в той же панели; затем проверка подключения; итог — точка состояния.
- Ошибка: черновик сохраняется, причина в панели (сервер уже вернул прежнюю конфигурацию), [Повторить].
- Профиль на устройстве обновляется сам.
- Уход с несохранёнными правками — «Применить / Отменить / Остаться».

### 5.4 Ноды на PHP-хостинге

В разделе Серверы, группа «Хостинг». Мастер — по правилам 5.1: шаги без нумерации (Хостинг: FTP или уже залита → Транспорт: Cups.online или Mail.ru → Установка с проверкой) → экран ноды. Экран ноды — форма 5.3, где вместо L3/L4 — [Запустить] / [Остановить] / [Панель ноды] / [Обновить состояние], ключ доступа с копированием; ⋮ — Удалить с хостинга (если можно), Убрать из приложения.

### 5.5 Это устройство (выходная нода)

Серверы → «Это устройство»: [Запустить ноду] / [Остановить]; на десктопе выбор L4/L3 (если поддерживается); порт `direct`, адрес для клиентов; QR и ссылка, когда нода работает. Пока устройство работает нодой, на Главной — баннер «Это устройство работает как нода» с [Открыть]. Переключатель «Клиент | Выходная нода» с Главной убирается.

## 6. Главная

1. Кнопка: состояние и время; ↓↑ скорость, пока подключено.
2. Строка подключения `[значок] Имя · группа ▾` — открывает шторку.
3. Чипы: «Весь трафик» (VPN на Android / TUN на десктопе, где поддерживается), «Системный прокси» (Windows, когда «Весь трафик» выключен).
4. Один баннер по приоритету: ошибка подключения ([Повторить] [Журнал]) → нужны права администратора ([Перезапустить]) → сессия Яндекса/Mail.ru истекла или просит проверку ([Войти заново]) → подписка требует продления ([Продлить]) → устройство работает нодой ([Открыть]).
5. «Сведения» (свёрнуто): сейчас через (транспорт), шифрование, бондинг, SOCKS5 и HTTP-прокси с копированием, внешний IP с [Проверить], трафик за сессию.

Нет подключений: экран «Приступим» — [Аккаунт OpenFlux], [Ключ или ссылка], [Свой сервер].

### 6.1 Шторка выбора подключения

Поиск (если подключений > 4). Группы «Подписка» (с строкой «До даты · Продлить»), «Мои серверы», «Остальные». Строка: отметка выбранного, имя, значки транспортов, точка «подключено». Нажатие — выбрать и закрыть; при активном подключении — переключиться. ⋮: Сведения, Изменить, Поделиться, Дублировать, Удалить; у своей ноды — «Открыть ноду»; у чужой ноды с сервером — «Это моя нода». Профили подписки — без изменения и удаления. Внизу [＋ Добавить]. На десктопе двойной щелчок — подключить.

### 6.2 Экран профиля

Шапка: имя, [Подключить] [Изменить] [Поделиться]. Транспорты — список (токены скрыты, ссылки копируются). Параметры — строки «Режим», «Шифрование», «Кодек», «Источник». Профиль подписки — строка «Приходит с подпиской» со ссылкой на подписку. Проблемы профиля — один баннер.

### 6.3 Редактор профиля

Функции сохраняются: имя, значок, режим Обычный / Session / Без сервера, основной и дополнительные транспорты (выбор из каталога, вход и создание документов, комнаты Cups.online, настройки JS-транспорта), бондинг, ключ шифрования с генерацией. Под «Дополнительно»: сеть, приоритет, кодек, контекст шифрования, ID пользователя MAX.

## 7. Добавить и Поделиться

### 7.1 Меню ＋

1. **Ключ, ссылка или файл** — одно поле, распознающее ключ подписки, ссылку `openflux://` или несколько строк; [Вставить] [Файл] [QR] (камера на Android; файл и буфер на десктопе — по возможностям платформы); превью под полем; одна кнопка [Добавить] / [Подключить подписку]. Входящие ссылки (сканер, системная ссылка) открывают этот экран с заполненным полем.
2. **Сканировать QR** — только при наличии камеры; результат — в экран 1.
3. **Свой сервер** — 5.1.
4. **Без сервера (хостинг)** — 5.4.
5. **Аккаунт OpenFlux** — 8.1.
6. **Вручную** — редактор профиля.

Диалог «Импорт профиля» и экран «Добавить подключение» с карточками убираются.

### 7.2 Поделиться

Первый экран: «Мои серверы» (ноды по серверам, включая ещё не добавленные на устройство — профиль добавляется сам), «Хостинг», «Остальные» (профили, которыми можно поделиться). Локации подписки не показываются.

Экран отдачи: крупный QR, [Копировать ссылку], одна строка «По этой ссылке подключится любой. Одновременно работает одно устройство — второе вытеснит первое» (для профилей «без сервера» — своя строка). Все «Поделиться» в приложении ведут сюда.

## 8. Аккаунт, Настройки, Журнал

### 8.1 Аккаунт OpenFlux

- Вход: вкладки «Вход | Регистрация», «Забыли пароль?» → восстановление (логин, ключ восстановления, новый пароль ×2).
- Лимит устройств: список и [Заменить].
- Ключ восстановления: группы, [Скопировать], отметка «Сохранил», [Продолжить]; строка о пробном периоде, если он начался.

### 8.2 Подписка (Настройки → Аккаунт OpenFlux)
